# 数据处理改动与验证边界

MIUI- 以本机和已授权手机之间的连接、文本剪贴板及按需投屏为目标。
以下内容描述这份固定版本副本实际修改的范围，不是厂商隐私政策，也不要求接受新的账号协议。

## 本地隐私政策界面

移除已确认的自动政策弹窗入口，并隐藏、禁用对应的界面入口。
补丁在创建协议对象或回调之前跳转到原有返回路径，不发送“接受协议”事件，
不新增、伪造或清除已有同意记录。只隐藏按钮与实际限制上报是两个独立改动。

手机确认、配对、账号和功能权限的检查继续执行；例如更新功能的服务权限判断仍然存在。
缺少必要功能授权时仍可能无法使用该功能，不会通过移除弹窗自动取得权限。
原组件仍有静态导入依赖，因此不能直接删除相关 DLL；第三方版权和许可说明也仍保留。

## 已禁用的统计路径

| 组件 | 修改范围 |
| --- | --- |
| MiDrop 旧 OneTrack | 不初始化统计 SDK；两个事件入口丢弃事件并执行原生参数析构，不保留待上报队列 |
| IDM 内置 OneTrackReporter | 不初始化报告服务；阻止 13 类指标共用的入队入口和上传循环 |
| PrivacyAuthorization 的 track 子系统 | 阻止隐私请求及反馈事件入队、遥测缓存写入、上传线程和对应 HTTP post 入口 |

这些修改由 `profiles/miui-2.5.5.643.json` 的精确原字节、修改范围和完整文件哈希限定。
没有对全部 socket、curl 或 DNS 做通用替换，局域网传输和配对协议仍走原生实现。
处理旧事件入口时保留原有字符串、属性对象与 map 的析构，不能用简单返回替代这些收尾工作。

PrivacyAuthorization 的初始化、清理仍配对，以免破坏 COM 或共享 curl 生命周期。
已阻止这里的上报队列和发送，但其初始化仍可能读取以前的缓存和准备本地监测对象。
既有缓存没有被自动删除。旧 SDK 的少数调用者仍可能短暂创建属性对象，随后在丢弃入口释放。

## 日志和必要的数据流

自有宿主不再为普通运行配置 IDM 的详细文件日志。
宿主的 `diagnostics` 仍记录启动阶段、组件版本、文件哈希、本地路径、进程编号和错误，
用于检查组件是否正确加载；宿主没有增加剪贴板内容或手机画面的日志记录。
厂商组件自身的其他默认日志不在这一声明内。

剪贴板同步本身需要在电脑与已授权手机间传输文本；投屏需要传输画面和控制消息。
手机确认、功能权限、配对信息和连接所需处理没有被伪造成登录成功或授权通过。
本项目没有新增自己的云端接口或分析服务。

## 不能据此推断的内容

本轮做了静态调用链分析、文件完整性验证和只运行自有指令的合成测试；
没有运行厂商程序或抓取实际流量。因此，“已禁用上述上报入口”不等于“所有外联均被阻断”，
也不等于已经完整审计全部闭源 DLL、默认日志和本地缓存。
没有改动系统防火墙、代理、证书或 hosts。

真实网络行为、剪贴板持续同步、关闭投屏后的占用和固件兼容情况仍需要设备所有者验证。
公开问题时请只提供必要错误信息，不上传原始私人日志、账号数据、密钥或手机内容。
