# 原生投屏与剪贴板的边界

## 为什么没有直接结束媒体进程

上一版在点击关闭时只隐藏窗口，手机仍可能发送画面。原生旧协议的 `CLOSE_SCREEN=0`
虽然暂停画面，却会把屏幕置为关闭状态；最后一个屏幕关闭时，手机可能释放高级连接引用。
`DESTROY_SCREEN=5` 释放更多对象，但同样可能触发连接降级或断开。
扫码连接不必然先建立基础通道，因此不能靠“结束媒体进程”保证剪贴板仍可用。

媒体 IPC 的发送函数先入队，立即退出还会丢失尚未写出的指令。
手机 `ON_HIDE` 也不带对应请求的关联信息，且发生在异步资源释放之前，不能冒充严格完成确认。

## 采用已有的主屏后台模式

参考手机组件已经支持 `UPDATE_MAIN_MODE=11`。这是已有投屏协议中的动作，
不是伪造登录、设备能力或连接标志。其 protobuf 字段为：

| 字段 | 编号 | 值 |
| --- | ---: | --- |
| `screen_id` | 2 | 主屏为 0 |
| `action` | 3 | 11 |
| `background_mode` | 11 | 停止画面时 true；重新打开时 false |

在参考手机代码中，旧 TCP 消息分派直接处理该动作。
主屏转入后台时，从虚拟显示上解绑编码 surface，停止并释放视频 MediaCodec，
保留显示对象、镜像源、连接组以及屏幕的已打开状态。
因此不会经过上述 `CLOSE_SCREEN` 的最后屏幕关闭计数与高级连接引用释放路径。
恢复前台时，原生路径重新创建、启动视频编码器并绑定 surface。

电脑端需要保留原生消息进程来发送恢复指令和处理会话；保留进程不代表持续传输画面。
此模式不等于销毁全部媒体对象：显示对象、镜像源、消息通道和部分电脑端缓冲仍会保留，
手机熄屏且存在活跃音乐时，原生后台模式还可能按其自身策略暂停或恢复播放。

关闭时先发送配套 `ProtoSimpleEvent`（消息类型 18）：事件字段 2 为 32
（`EVENT_PAD_SOUND_ON`），布尔 oneof 字段 6 为 true。
这是原生折叠主屏的音频解除动作；只有主屏音源时会停止并释放录音，存在其他子屏音源时不影响它们。
该消息也不修改系统音量。

恢复时只发送视频模式 false，不主动发送音频 false。手机的音频 false 会直接重新挂接音源，
而旧 PC 尚无已验证的接口可读出用户此前的音频偏好，不能擅自开启它。
因此本版重新打开画面默认静音，尚无独立音频恢复入口；也没有证据表明旧 UI 音量按钮即可恢复该音源。

两条关闭请求按“音频 → 视频”的顺序提交。第一条本地失败时不提交第二条；第二条本地失败时
保持窗口可见，视频未被请求暂停，用户可再次关闭重试。底层发送异步，不是远端原子事务。
本地函数返回成功不是手机处理确认，网络异常下仍可能只有部分请求送达。

## 电脑端实现

`tools/background_video.S` 是自有汇编，`background_video_transform.py` 验证全部输入后添加
只读可执行的 `.bgvideo` 节，重定向关闭和隐藏窗口恢复处的两个 call。
其余原生窗口序言、激活回调、导入、重定位、CFG 配置保持不变；原异常表逐项保留并增加
三个自有函数的 x64 unwind 信息。无可写可执行节、额外线程或新的远端接口。

主屏由原生 `screen_id=0` 限定；应用副窗口保留上一版隐藏/显示行为，不能将其描述为已经停止编码。
补丁不关闭媒体进程或释放全部电脑端解码器和渲染对象，仍可能有系统重绘和消息轮询。
手机停流后已排队的数据也需要被消耗完，因此本次没有声称 CPU/GPU、网络或内存占用降至零。

自有封包最多 20 字节，使用原生分配器分配 32 字节；正常返回时由双方约定的单一所有者释放。
底层原生函数抛出内存分配等 C++ 异常时，本次没有新增专用异常清理处理器，不能声称所有异常路径都无泄漏。
源/输出哈希、所有修改范围及分支地址均严格校验；编译自己的汇编可再比对嵌入字节。

## 剪贴板归属

默认连接时不自动启动媒体窗口，没有媒体 IPC 客户端时由 Guide 处理文本剪贴板。
手动打开过画面后，媒体消息进程仍保留；原有去重逻辑继续生效，避免 Guide 与媒体重复投递。
关闭主屏画面不调用断开设备、退出 Guide 或退出 MIUI+。
真正需要完全断开时，仍使用软件自己的退出或断开操作。

- PC 原始 MIUI+：2.5.5.643 x64；固定输入、修改范围和输出哈希由构建 profile 限定。
- 参考手机 APK：`com.xiaomi.mirror` 17.01.30；SHA-256：
  `a9038ff0145ebbe000a6e127b36fce2cd2847fce1f21d37b7d8c65c5aacde717`。
- 已核查的手机链：`MessageHandlerImpl` → `U.g1` → 主屏 `A.x0` → 编码器 `H.e1/O0/M0`。
- 设备所有者报告的实际组件为 17.01.31-07.10，设备互联为 17.2.2.0.2603231034；
  本次没有该精确版本 APK，因此参考版本不能替代真机验证。

本次只做文件静态分析、构建和自有离线测试，未自动启动厂商程序、控制桌面或连接手机。
