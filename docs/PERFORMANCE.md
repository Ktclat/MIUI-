# 启动校验优化

每次启动仍完整验证 61 个可执行组件的 SHA-256。优化没有改成只看文件大小或修改时间，
也没有用上一次成功结果绕过其他进程自己的验证。

主要变化：

- 使用 Windows 自带 CNG 的 SHA-256，替换原先较慢的托管实现。
- 同一次顺序读取中完成哈希和连接管道字段检查；复用 1 MiB 缓冲区。
- 已有 UIHost 与入口文件逐字节哈希一致时，跳过重复复制。
- 保留父进程身份、加载路径、额外 DLL 拒绝、版本、取消和启动就绪检查。

## 本地测量

2026-10-25，Windows / .NET Framework 4.0.30319.42000；61 个文件共 451,077,384 字节。
两个独立控制台进程分别执行旧、新 `Candidate.Validate`，各预热一次后测量三次。
没有清空 Windows 文件缓存，没有启动小米程序、界面或手机会话。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 文件校验耗时中位数 | 7,489.02 ms | 382.42 ms |
| 文件校验 CPU 时间中位数 | 7,437.50 ms | 375.00 ms |
| 三次耗时 | 7740.63 / 7489.02 / 7442.23 ms | 381.90 / 389.31 / 382.42 ms |

这是**启动过程中的本地文件验证**，不是完整软件启动时间、连接耗时、待机占用或手机耗电测量。
其他磁盘、缓存状态和系统负载下结果会不同。

旧自有控制器源码 SHA-256：
`8a19de9abfb549cac7adc1ffeb47aa7a19762b945dcfd5a6721907540ee43505`。
优化后源码 SHA-256：
`0b7595f4d5a047577e05db2f9b76ccc66487382e3b83280bef7953f72085e4ec`。
上述比较使用同一份旧候选组件清单，不把后续协议修改混入速度比较。

## 在自己的机器测量

准备完整合法的本地候选后，执行：

```powershell
powershell -File .\src\controller\benchmark.ps1 -CandidateDirectory '.\artifacts\local\app'
```

可用 `-BaselineSource 'D:\PreviousSource\CompatController.cs'` 同时测量自己保留的上一版源码。
基线必须使用相同的候选文件和当前固定清单；不要更改白名单来掩盖文件差异。
脚本只编译、运行自有的离线文件检查入口；结果保存在已被 Git 忽略的 `benchmark-build` 内。
原始报告可能包含本机路径，公开前应去除这些信息。
